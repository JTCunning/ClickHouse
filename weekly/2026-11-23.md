## Review bot
What the bot checks differently since last week (prompt changed 2026-11-16, 11-18 and 11-19; the CI job 11-16, 11-17 and 11-19):
- 2026-11-16: a new check for build changes that weaken security hardening (stack protector, `_FORTIFY_SOURCE`, PIE, RELRO, CFI, hardened libc++ and similar), globally or for one target, file or function, including a per-function sanitizer opt-out. The PR must state the failure, its root cause and why the cause can't be fixed instead; an unexplained opt-out in a release build is a Blocker. For us: never add a sanitizer opt-out to get past a check. The #26 rework this week moved the arithmetic back inline instead.
- 2026-11-17: when the model provider stops a review session as a possible cybersecurity risk (the review then falls back to an older model and can miss the finding that triggered the stop), the run no longer approves, and it dismisses earlier approvals. Parsers and binary-data readers are the PRs most likely to hit this.
- 2026-11-18: a new check, "destroying and re-creating in place". When code frees an aggregate state and builds a new one in the same memory, a failing build (for example a memory limit) must not lead to a second free later. The grid functions had a related bug this week (#132219: states not freed when reserving the result throws). None of my open branches has such code.
- 2026-11-19: the job reads the verdict from one exact line, `Status: ✅ Approve` (lenient fallback when that line is missing).
- 2026-11-16: the GitHub approval is submitted without a body (no rule change).

The preflight skill is now v1.3.0. Study runs also brought v1.2.3 (Style Check rejects plain std containers in more directories) and v1.2.4 (perf-test traps: the Iceberg rerun of perf XMLs with MergeTree tables, literal braces in perf queries).
