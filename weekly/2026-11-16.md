## Review bot
What the bot checks differently since last week (the prompt changed 2026-11-10 to 11-13, the CI job on 11-16):
- 2026-11-10: an unresolved `[Blocker]` thread (or any untagged human comment) now holds the full CI and the merge; only builds, Fast test and Style Check run until it is resolved. Inline comments are tagged `[Blocker]` or `[Major]`.
- 2026-11-10 and 11-13: code that reads back stored or received binary data (aggregate states, part files, caches, replica data) must check every assumption and throw on bad bytes; sizes computed from counts must not overflow. For us: any grid-state or cache change needs a crafted-input test.
- 2026-11-12: for a bug fix, the bot walks the triggering input through the unchanged lines of the touched functions too; a defect it finds there counts, even if old (this is how #17's anchoring bug surfaced in my own preflight).
- 2026-11-13: new "Preconditions" gate: what the changed code assumes about sizes and indexes, and who produces each value.
- 2026-11-16 (https://github.com/ClickHouse/ClickHouse/pull/131876): a ✅ Approve is now a real GitHub approval of the head commit; a later run that does not approve dismisses it. So every follow-up push (rebase, nit fix) is a new first try: batch fixes and preflight each push.
The preflight skill is now v1.2.2.
